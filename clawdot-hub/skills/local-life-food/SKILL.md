# 本地生活任务（外卖）

### 先连上任务接口

这份说明配的是任务接口上的一组工具，由 `create_task` 起头。调不到 `create_task`，就是这个客户端还没连上任务接口：先停下来帮用户连上；没连上之前什么都查不到、也下不了单，不要自己编结果。各客户端的连法都一样：

- 任务接口的地址：https://hub.clawdot.net/mcp/task
- 在客户端里添加一个远程 MCP 连接，地址填上面这个（各客户端在哪里添加，登录 https://hub.clawdot.net 后在「接入」里按平台查）。连接时会打开连接页：登录（或注册）开发者账号，选一个专用 agent（或新建一个），回到客户端就连上了。
- 客户端打不开浏览器（自建 agent、没有屏幕的设备）：走设备码授权，用户在任意一台能上网的设备上打开链接、输入码，同样登录开发者账号、选专用 agent；这条要先由虾点建档、拿到 client_id。
- 自己的服务端对服务端接入：用 API Key 接任务接口，每个请求带上自己这边的用户编号；API Key 由虾点发放（在控制台申请）。
- 连上以后工具列表里就有 `create_task` 了，照下面「怎么走」办。

这组工具按「一单一个 task」走：先开 task，之后每一步都照返回里的下一步去调。
每个参数什么意思、哪一步会被拒，工具说明和返回里都有，这里不重复；这里只讲工具判断不了、要你来判断的事：用户到底想要什么、几个 task 怎么记、对用户怎么说。

## 1. 怎么走

- 每一单先调 `create_task`，只带 `idempotency_key` 和 `context`，不用带 `capability`。这一次和之后每次调 `create_task`、`update_task` 与各组工具，都在 `context` 的 `utterance` 里放用户这一轮说的原话，逐字照抄，不改写、不总结；这一步用户没说新话（你自己往下走）就带用户最近说的那一句。
- `idempotency_key`（`create_task`、`fork_task` 都要带）：每开一单生成一个随机 UUID，只在同一次调用超时重试时带同一个；不要按内容、日期、序号起名，也不要沿用别的单用过的键。
- 刚开的 task 还没定办什么，返回里的 `next_action.summary` 列了各业务的第一步：点外卖从 `food_address` · `search` 开始。第一次调了哪个业务，这个 task 就归哪个业务，之后不能再调别的业务；用户中途又要办另一件事，用新的 `idempotency_key` 另开一个 task。
- 之后照返回里的 `next_action.tool`、`next_action.action` 调，每次都带 `task_id`。`next_action.options` 原样摆给用户挑，用户挑中的那一项的 `ref` 原样回传，不改、不自己拼。
- 已经往后走了（选了店、加了购）又回头搜地址、搜店，只算「只是看看」：已选的东西一样不动，`next_action` 仍指着原来那一步（比如 `food_cart` · `preview`），搜到的候选不在 `next_action.options`，在 `result.candidates`。摆给用户看就好；用户要换，再拿其中一项的 `ref` 调 `select`，`summary` 里写了换了会清掉什么。重选同一个地址什么都不清。
- 要下单，用确认页那一项的 `ref` 当 `confirm_ref`，而且要等用户同意之后。什么算同意下单：
  - 只有用户**看过这张确认页的实付之后**、针对它说「下单 / 确认 / 就这样」才算同意。
  - 在确认页出来之前说的「结算 / 买单 / 下单吧」，只表示「出确认页给我看」：调 `food_cart` · `preview` 之后，先把店名、商品、实付摆给用户，问一句「确认下单吗？」，等用户回复再调 `food_place_order`。
  - 「继续」「往下走」「你直接帮我选」都不算同意下单。
  - 用户回的是问题或别的事，先答，再问一次要不要下单。

- 外卖不能取消。

- 用户问订单（「看看我之前的单」「上一单到哪了」），任何时候都能查，不用管 task 走到哪一步：在手头的 task 里（刚开的也行）调 `food_fulfillment` · `list` 列最近的单，要看某一单就带它的 `order_id` 调 `status`。查单不会清掉已选的东西，查完接着原来那一步走。

## 2. 一个 task = 一家店 = 一单

- 一个 task 只装一家店的东西，最后只成一单。两家店就是两个 task、两单、两次付款。
- 每开一个 task 都算一次费。不要为了「先看看」去开 task；比较别家店用搜店（见 4）。

## 3. 下单前改主意

- 有两种回退，按用户的意思选：
  - 只想改一项：在原 task 里重调定这一项的那一步，比如换地址重调 `food_address` · `select`，删一样用 `food_cart` · `remove`。不开新 task、不多计费。
  - 想留着现在这一版、另试一版（「先别动这个，再配一份看看」）：对原 task 调 `fork_task`，带新的 `idempotency_key`。新 task 带着地址、店和购物车里的东西，原 task 原样留着，之后哪一版都能接着走到下单。fork 会多计一次费；购物车里有加不回来的商品时返回里会列出来，要跟用户说一声。
- 有的改动会清掉后面已经选好的东西，比如换店会清空购物车。哪一步清什么见 @references/rollback.md；会清掉用户已经挑好的东西时，先跟用户说清楚再调。
- 下了单就回不去了：再要一单调 `create_task` 新开；「照上一单再来一份」用 `fork_task`。两个都要带这一单新的 `idempotency_key`，超时重试带同一个。还没开始办事的 task、下单结果不明的 task 不能 fork。

## 4. 用户要另一家店的东西（外卖）

购物车里已经有东西，用户又提到另一家店时（下面叫 A 店、B 店），先判用户是哪种意思：

| 用户的意思 | 怎么走 |
|---|---|
| 换成 B（没说 A 的东西不要了） | 说清购物车里哪几样会被清掉，用户同意了，再在这个 task 里搜到 B 店、用 `food_browse` · `select` 选它。用户已经明说「A 的不要了」，就直接换，回复里说一声购物车清掉了 |
| B 的也要（两单） | 不动这个 task。用新的 `idempotency_key` 调 `create_task` 另开一个，地址从已存地址里选同一个。记好「哪家店 ↔ 哪个 `task_id`」，记不清就对各个 `task_id` 调 `get_task` |
| 想换 B 又怕后悔（想比较着换） | 先对这个 task 调 `fork_task`（新的 `idempotency_key`），在新 task 里搜 B 店、选它；原 task 的购物车原样留着，用户最后要哪一版就在哪个 task 里下单 |
| 只看看 B | 在原 task 里用 `food_browse` · `search` 搜店（不清任何东西）。候选在 `result.candidates`，`next_action` 仍指着购物车那一步，`summary` 写了购物车有几件、换店会清空。不选店，不开新 task。用户拍板后再按上面三行走 |
| 回 A 的菜单 | `food_browse` · `menu`。**不要重选 A**：重选同一家店也会清空购物车 |
| A 已经下了单，再要 B | 调 `create_task` 新开一个。不用 `fork_task`（它是照旧单再来一份） |

分不清就只问一句：「换成 B 店，还是两家都要？」不要猜。

## 5. 两单怎么确认

- 两家都加好以后，挨着各自预览（`food_cart` · `preview`），把两张确认页摆在同一屏：各写店名、买了什么、实付多少，讲明是两份配送费、两次付款。
- 用户明确说两单都下，才两单一起下，各用各的确认页那一项的 `ref`；否则一单一单问、一单一单下。
- 两单来回切，找不准某一单的确认页了，就对那个 `task_id` 调 `get_task` 取回；确认页已经过期，就重新预览那一单。

## 6. 点外卖时怎么问、怎么摆

工具返回给的是事实和下一步；要不要问、怎么问，看用户说了什么来定。原则：能不问就不问，要问就一句问完。

- **地址**：已存地址只回了一个，直接选，到确认页时说一句送到哪。有好几个时，记忆给其中一个打了标签（如「上一单的地址」「按你的偏好」）的就默认它，问一句「还是送到 X 吗？」；都没有标签，摆出来让用户挑，不替用户选。
- **搜店：有方向才带关键词**。用户说了店名、品牌、品类或口味，带 `keyword` 搜；没有方向（「饿了」「随便来点」），不带 `keyword`，直接看附近的店，别反问「想吃什么」。
- **规格**：看规格那一步的 `next_action.summary` 以「默认：」开头列了默认组合，照它一句话问完：「默认中杯、少冰、全糖，要改哪项？」。默认就是最低价的，也可以不等回话、按默认先加购，但同一条回复里要说清按的是哪个默认、告诉用户可以改；默认不是最低价的，见下条，先问价，不先加购。选填的不主动问，用户自己提了才加。
- **价格档**：用户自己说了规格就按用户说的。默认就是最低价时照上面问；标「默认：是」的不是价格最低的那档（「最低价：是」在别的档上），把各档价格和其余默认并成一句让用户选：「中杯 ¥18、大杯 ¥22，要哪个？其余默认少冰、全糖」，不替用户默认贵的。
- **单点不送**：摆商品时遇到标了「单点不送：是」的，提醒一句要再凑点别的才送。
- **凑单**：被单点不送拦下，或购物车的 `next_action.summary` 写着「还差 ¥X 起送」，从这家店已拉到的菜单里推荐 2–3 样（热销的或便宜的），最多 3 样，不要把菜单列出来，别换店。
- **招牌**：用户点名的东西在某家店候选的「招牌」里，认出是哪家，直接去那家找到它，不让用户翻整本菜单。

## 7. 对用户说话

- 不说工具名、`task_id`、`ref` 这些；说店名、菜名、价钱。
- 两单就说两单（「A 店一单、B 店一单，分开付」），不要说成一单，也不要只报一个合计让用户以为只付一次。
- 金额只用确认页上的实付，不自己估。
